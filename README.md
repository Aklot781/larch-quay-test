# Larch Quay

## Отчёт

В рамках задания проведён анализ производительности сайта Larch Quay и выполнены первые оптимизации с учётом жалоб клиента.

### 1. Что было найдено

При первоначальной проверке и анализе проекта обнаружены следующие проблемы:

| Проблема | Где обнаружена | Критичность |
|---|---|---|
| Очень долгая загрузка страницы на мобильных устройствах | Общая загрузка страницы | Критическая |
| Большой размер JavaScript и CSS | Production-сборка Vite | Высокая |
| Большое количество загружаемых ресурсов | Загрузка страницы | Высокая |
| Крупные изображения | Изображения проекта | Высокая |
| Повторная загрузка данных квартир | `App.svelte`, `FlatModal.svelte` | Средняя |
| Дополнительная нагрузка на основной поток JavaScript | Работа приложения | Высокая |
| Возможные сдвиги элементов при загрузке | Макет страницы | Средняя |
| Тяжёлое фоновое видео | Главный экран | Средняя |

### 2. Что было исправлено

**Оптимизация production-сборки**

В `vite.config.js` удалены настройки:

- `minify: false` — отключала минификацию JavaScript.
- `assetsInlineLimit: 10485760` — позволяла встраивать ресурсы размером до 10 МБ непосредственно в сборку.

После удаления этих параметров Vite использует стандартную минификацию и стандартный порог встраивания ресурсов. CSS также формируется отдельным файлом.

**Оптимизация загрузки данных**

- Удалён отладочный `console.log` из расчёта ипотечных платежей.
- Повторно используется уже загруженный список квартир.
- Убрана дополнительная загрузка общего списка квартир при открытии карточки. Данные похожих квартир берутся из уже загруженного списка.

### 3. Как проверялась работа

Для проверки использовались Lighthouse в Microsoft Edge и production-сборка проекта.

Настройки Lighthouse:
- Устройство: Mobile.
- Режим: Navigation.
- Категория: Performance.
- Адрес: `http://localhost:4173/`.

**Результаты до оптимизации**

| Показатель | До |
|---|---:|
| Performance | 27 |
| First Contentful Paint (FCP) | 107,3 с |
| Largest Contentful Paint (LCP) | 279 с |
| Total Blocking Time (TBT) | 1350 мс |
| Cumulative Layout Shift (CLS) | 0,102 |
| Speed Index | 121 с |
| Количество запросов | 764 |
| Общий объём ресурсов | 188 207 КиБ |

**Результаты повторного тестирования**

| Показатель | После |
|---|---:|
| Performance | 23 |
| First Contentful Paint (FCP) | 5,2 с |
| Largest Contentful Paint (LCP) | 100,7 с |
| Total Blocking Time (TBT) | 51 360 мс |
| Cumulative Layout Shift (CLS) | 0,102 |
| Speed Index | 30,2 с |
| Количество запросов | 764 |
| Общий объём ресурсов | 187 773 КиБ |

Повторный тест показал улучшение FCP и Speed Index, однако итоговый балл Performance снизился, а TBT значительно вырос. Поэтому пока нельзя считать, что общая производительность страницы улучшилась.

Для более точного сравнения необходимо повторить тестирование в одинаковых условиях и дополнительно проверить результаты на реальном мобильном устройстве.

**Сравнение размеров production-сборки**

| Файл | До | После |
|---|---:|---:|
| JavaScript | 29 267,33 КБ | 1 840,82 КБ |
| JavaScript gzip | 19 401,63 КБ | 530,78 КБ |
| CSS | 1 567,25 КБ | 452,06 КБ |
| CSS gzip | 850,90 КБ | 73,74 КБ |
| Polyfills | 167,82 КБ | 54,04 КБ |
| Polyfills gzip | 31,22 КБ | 18,50 КБ |

В результате:
- Размер JavaScript уменьшился примерно на 93,7%.
- Размер JavaScript gzip уменьшился примерно на 97,3%.
- Размер CSS уменьшился примерно на 71,2%.
- Размер CSS gzip уменьшился примерно на 91,3%.

Production-сборка успешно создаётся командой `npm run build`.

Проверка на реальном телефоне и полноценное повторное тестирование всех пользовательских сценариев не завершены.

### 4. Что можно сделать дальше

- Оптимизировать крупные изображения и перевести их в WebP или AVIF.
- Реализовать ленивую загрузку изображений и видео.
- Оптимизировать фоновое видео для мобильных устройств.
- Разделить JavaScript на более мелкие чанки и загружать необходимые части приложения по мере использования.
- Проверить причины высокого Total Blocking Time.
- Проверить размеры изображений и зарезервировать место под них для уменьшения сдвигов макета.
- Повторно провести Lighthouse-тестирование и проверить сайт на реальном мобильном устройстве.

## О проекте

Larch Quay — landing page жилого комплекса с галереей изображений, информацией о домах, расположении и интерактивными элементами.

## Технологии

- Svelte
- Vite
- JavaScript
- CSS

## Требования

- Node.js 24

## Установка

```bash
npm install
```

## Команды

- `npm run dev` — запуск сервера разработки по адресу `http://localhost:5173`.
- `npm run build` — создание production-сборки в папке `dist`.
- `npm run preview` — запуск локального просмотра production-сборки по адресу `http://localhost:4173`.
