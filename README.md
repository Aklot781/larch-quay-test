# Larch Quay --- оптимизация производительности

## О проекте

Larch Quay --- веб-сайт жилого комплекса с галереей изображений,
информацией о домах и расположении, а также интерактивными элементами.

## Цель работы

Проверить производительность проекта, выявить наиболее заметные узкие
места и выполнить приоритетные улучшения без масштабной переработки
приложения.

## Технологии

-   Svelte
-   Vite
-   JavaScript
-   CSS

## Запуск проекта

Установить зависимости:

``` bash
npm install
```

Запустить режим разработки:

``` bash
npm run dev
```

Создать production-сборку:

``` bash
npm run build
```

Запустить локальный просмотр production-сборки:

``` bash
npm run preview
```

Для проверки производительности использовалась именно production-сборка,
запущенная через `npm run preview`, а не режим разработки.

## Выполненные оптимизации

### Настройки production-сборки Vite

В `vite.config.js` удалены настройки:

-   `minify: false` --- отключала минификацию JavaScript;
-   `assetsInlineLimit: 10485760` --- разрешала встраивать файлы
    размером до 10 МБ непосредственно в сборку.

После удаления этих параметров Vite использует стандартную минификацию и
стандартный порог встраивания ресурсов.

В результате изображения и другие ресурсы стали формироваться отдельными
файлами, а JavaScript и CSS уменьшились.

### Сравнение размеров сборки

Размеры файлов до и после изменения настроек:

  Файл                          До         После
  ----------------- -------------- -------------
  JavaScript          29 267,33 КБ   1 840,88 КБ
  JavaScript gzip     19 401,63 КБ     530,79 КБ
  CSS                  1 567,25 КБ     452,06 КБ
  CSS gzip               850,90 КБ      73,74 КБ
  Polyfills              167,82 КБ      54,04 КБ
  Polyfills gzip          31,22 КБ      18,50 КБ

Изменение размера:

-   JavaScript уменьшился примерно на 93,7%.
-   Сжатый JavaScript уменьшился примерно на 97,3%.
-   CSS уменьшился примерно на 71,2%.
-   Сжатый CSS уменьшился примерно на 91,3%.

### Что ещё требует внимания

По результатам первоначального анализа были замечены следующие
потенциальные проблемы:

-   большой объём данных в `public/api/flats.json`;
-   повторные запросы к данным квартир и дополнительные запросы
    `/api/flats/{id}.json`;
-   тяжёлое фоновое видео;
-   изображения большого размера;
-   возможные сдвиги макета из-за изображений без заданных размеров;
-   длительные задачи JavaScript в основном потоке.

## Итог

На текущем этапе оптимизирована production-сборка Vite: включена
стандартная минификация и прекращено чрезмерное встраивание ресурсов в
JavaScript.

Размер основного JavaScript-файла уменьшился с 29,27 МБ до 1,84 МБ. Для
завершения проверки необходимо повторно запустить Lighthouse и сравнить
показатели производительности, количество запросов и общий объём
загруженных ресурсов.

# Отчёт по оптимизации производительности

## 1. Найденные проблемы

До оптимизации проект имел следующие проблемы:

| Проблема | Приоритет |
|---|---|
| Очень долгая загрузка страницы на мобильных устройствах | Критический |
| Большой размер JavaScript и CSS | Высокий |
| Большое количество загружаемых ресурсов | Высокий |
| Сдвиги элементов страницы во время загрузки | Средний |
| Возможная избыточная загрузка данных квартир | Средний |
| Большие изображения, увеличивающие время загрузки | Высокий |
| Дополнительная нагрузка на основной поток браузера | Высокий |

## 2. Результаты до оптимизации

Первоначальное тестирование выполнено через Lighthouse в Chrome DevTools в режиме Mobile, Performance, Navigation.

| Largest Contentful Paint (LCP) | 279 с |
| Total Blocking Time (TBT) | 1350 мс |

| Общий объём ресурсов | около 184 MiB |

## 3. Выполненные изменения

- Включена минификация JavaScript при production-сборке.
- Убрано встраивание крупных ресурсов в JavaScript.
- Включено разделение CSS на отдельные файлы.
- Удалён отладочный `console.log` из расчёта ипотечных платежей.
- Повторно используется уже загруженный список квартир вместо дополнительного запроса за теми же данными.
- Устранена дополнительная загрузка списка квартир при открытии карточки, для получения похожих квартир используется уже загруженный список.

## 4. Результаты production-сборки

## 6. Что можно улучшить в дальнейшем

- Оптимизировать крупные изображения и использовать современные форматы WebP/AVIF.
- Реализовать ленивую загрузку изображений и видео.
- Разделить JavaScript на более мелкие чанки и загружать необходимые части приложения по мере необходимости.
- Дополнительно оптимизировать анимации и работу с видео на мобильных устройствах.
- Проверить возможность уменьшения количества сторонних библиотек и нагрузки на основной поток браузера.
